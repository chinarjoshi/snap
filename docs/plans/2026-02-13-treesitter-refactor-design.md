# tree-sitter Refactor Design

## Context

SNAP (Structured Notes ANTLR Parsers) currently uses ANTLR to generate parsers in Go and Swift. We're replacing ANTLR with tree-sitter to get a C parser that works natively in both Swift (iOS) and Emacs. Go support is dropped. The project becomes SNAP (Structured Notes tree-sitter Parsers... close enough).

## Architecture

All domain logic lives in C. tree-sitter generates the parser from a JavaScript grammar definition. A C library walks the parse tree and builds typed result structs. Swift and Elisp are thin wrappers over the C API.

### Repo Structure

```
snap/
  grammars/
    workout/
      grammar.js              <- tree-sitter grammar definition
      src/                    <- generated by tree-sitter generate
        parser.c
        tree_sitter/parser.h
  lib/
    workout.c                 <- domain logic: tree-walk + build WorkoutResult
    workout.h                 <- C API: workout_parse() -> WorkoutResult*
  swift/
    Package.swift
    Sources/
      CSnap/                  <- ONE C target, includes all grammars + all lib/*.c
        module.modulemap
      SnapParsers/            <- ONE Swift target wrapping all C parsers
        Workout.swift         <- thin wrapper: C structs -> Swift types
        Models.swift          <- WorkoutResult, Exercise, WorkoutSet
    Tests/
      SnapTests/
  emacs/
    snap.c                    <- ONE dynamic module, registers all parsers
    snap.el                   <- Elisp integration with org-mode
    Makefile                  <- builds one .dylib
```

### C API

```c
typedef struct {
    int reps;
    int weight;
    char note[256];
} WorkoutSet;

typedef struct {
    char name[256];
    WorkoutSet *sets;
    int set_count;
} Exercise;

typedef struct {
    Exercise *exercises;
    int exercise_count;
    char **prose_lines;
    int prose_count;
} WorkoutResult;

WorkoutResult *workout_parse(const char *input);
void workout_result_free(WorkoutResult *result);
```

`workout_parse` runs tree-sitter, walks the CST, applies the isWorkout heuristic (>=2 sets, has weight), and returns NULL for non-workouts.

### Swift Wrapper

A thin layer converting C structs to Swift value types:

```swift
import CSnap

public func parse(_ input: String) -> WorkoutResult? {
    guard let cResult = workout_parse(input) else { return nil }
    defer { workout_result_free(cResult) }
    return WorkoutResult(from: cResult)
}
```

Models stay the same: WorkoutResult, Exercise, WorkoutSet. The 27 existing test cases carry over with identical inputs and expected outputs.

### Emacs Integration

The emacs Makefile compiles the same C source into a dynamic module. The C module entry point converts WorkoutResult structs into native Elisp objects (alists, vectors) using the Emacs module API.

```elisp
(require 'snap)
(snap-workout-parse "squat 3x8x225")
;; => ((exercises . [((name . "Squat") (sets . [...]))]) (prose . []))
```

A thin .el file hooks into org-mode to detect double-enter and call the parser on the preceding paragraph.

### tree-sitter Grammar

Port of the ANTLR grammar to tree-sitter's JavaScript DSL. Same structure: paragraph -> lines -> exercise_line | continuation_line | superset_line | prose_line. Named fields replace ANTLR labels for accessing reps, weight, sets in multiplier/by rules.

### Domain Logic in C

The workout.c file ports the visitor logic as a tree-walking state machine:

1. Walk child nodes of paragraph
2. exercise_line: extract name, build sets from numeric tokens
3. continuation_line: extend previous exercise's sets with weight carryover
4. superset_line: alternate sets between two exercises
5. prose_line: collect into prose array
6. Apply isWorkout heuristic

Same algorithm as current Go/Swift, just switch on ts_node_type() instead of visitor dispatch.

## Adding Future Parsers

Adding a new parser (recipe, TODO, calendar):

1. Write `grammars/<type>/grammar.js`, run `tree-sitter generate`
2. Write `lib/<type>.c` + `lib/<type>.h` (domain logic + C API)
3. Add a Swift wrapper function in `SnapParsers/` (~20 lines)
4. Register one more C function in `snap.c` (~5 lines)

No new build targets, no new module loading. All parsers compile into one C library, one Swift package, one Emacs module.

## What Gets Dropped

- All Go code (libs/workout/, cmd/snap/, go.mod, go.sum)
- ANTLR grammar (Workoutliner.g4)
- ANTLR generated files (lexer, parser, visitor, listener)
- ANTLR Swift dependency
- ParagraphASTVisitor.swift, WorkoutLiner.swift

## What Stays

- Models (WorkoutResult, Exercise, WorkoutSet) — same types
- All 27 test cases — same inputs, same expected outputs
- README.org — updated
- Design docs
